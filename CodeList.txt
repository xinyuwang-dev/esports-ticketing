## 3. Predominantly AI-assisted

### Redis inventory and order services

Files:

- src/main/java/com/xinyu/esportsticketing/service/RedisStockService.java
- src/main/java/com/xinyu/esportsticketing/service/RedisOrderService.java
- src/main/java/com/xinyu/esportsticketing/service/RedisInventoryInitializer.java

Student contribution: defined Redis as an optional pre-filter, retained MySQL
as the authoritative persistent store, selected and integrated the final
behaviour, and verified the application and happy path.

AI assistance: OpenAI ChatGPT and OpenAI Codex substantially assisted with the
Lua stock check and decrement, Redis key operations, delegation to the MySQL
OrderService, limited compensation after a runtime failure, and conditional
startup initialisation. Git blame attributes all current lines of
RedisStockService and RedisOrderService to f26f937 and all current lines of
RedisInventoryInitializer to 7dc6a8a.

Actual behaviour: mysql mode calls the MySQL OrderService directly. Redis mode
performs the Lua reservation first, then calls the same MySQL transaction. Both
modes persist final stock and orders in MySQL, whose pessimistic lock remains
the final correctness protection. Compensation is a limited Redis increment;
there is no automatic fallback, retry, or reconciliation. The initializer is
created only when app.order.mode is redis.
